# 人类阅读计划：从零接手这台已迁移的服务器

这不是按文件名“随便看看”的计划，而是一条从全局目的到可操作细节的路线。阅读时不要先下载大文件、也不要先翻 Codex JSONL。

## 15 分钟：确认你现在该做什么

1. 根目录 `00_请先读我_服务器迁移总蓝图.md`：看研究路线、迁移边界与容量结论。
2. `MIGRATION_STATUS.md`：确认哪些包已验证、哪些仍待办。
3. `docs/01_研究总览.md`：读“V7 和 AL 尚未集成”这条最重要事实。
4. `projects/goai-v7-active-learning/CURRENT_STATE.md`：了解当前问题与接口缺口。
5. `projects/goai-v7-active-learning/NEXT_STEPS.md`：知道恢复后的第一步。

完成标准：能够不用打开任何旧 run 或聊天历史，回答“当前主线是什么、V7 是什么、AL 已做/未做什么、下一个最小实验是什么”。

## 60 分钟：能安全恢复当前主线

| 顺序 | 文件 | 你要得到的答案 |
|---:|---|---|
| 1 | `projects/goai-v7-active-learning/V7_BASELINE.md` | 哪三组 seed 是可恢复基线？哪些结论不应过度解释？ |
| 2 | `projects/goai-v7-active-learning/DATA_CONTRACT.md` | 哪些 CSV 私有？如何对齐、mask、防泄漏？ |
| 3 | `projects/goai-v7-active-learning/ACTIVE_LEARNING_PLAN.md` | 为什么不能把现有 AL 说成 V7-AL？接口须冻结什么？ |
| 4 | `projects/goai-v7-active-learning/DECISIONS.md` | BCR 为什么不再是 active required？ |
| 5 | `manifests/artifacts.yaml` | 需要哪个逻辑包、在哪里、哈希是什么、解压到哪里？ |
| 6 | `docs/04_存储与访问说明.md` | 如何从 Drive 下载、校验和解压？ |

完成标准：能够只下载 V7 必需包，校验后恢复到新机器；不会误把 BCR/旧 OOF/缓存当作当前输入。

## 90–150 分钟：完整理解研究与历史选择

1. `docs/02_研究路线与决策史.md`：看 GeneDisco → GO-AI 第一阶段 → V7/AL 的因果链。
2. `docs/03_原服务器文件地图.md`：理解原来为什么有数十 GB、哪些变成 metadata-only。
3. `projects/genedisco/README.md`：理解主动学习入门项目的可迁移方法价值。
4. `projects/goai-stage1/README.md`：理解 M12 交付和 M10/RNA 支线为何归档。
5. `projects/biohub/README.md`：理解 Biohub 的两份 dirty worktree 为什么不可合并。
6. `docs/05_新机器恢复手册.md`：检查完整恢复路径与 smoke test。

完成标准：能够解释每个大目录为什么被完整搬运、精选搬运或只留清单，并能定位历史证据。

## 仅在需要时：Codex 历史与个人状态

1. `docs/06_Codex_完整归档与恢复指南.md`；
2. `docs/07_Codex_会话与上下文索引.md`；
3. 私有、加密的 `90_CODEX_PRIVATE_COLD_BACKUP/`。

不要用完整 Codex 档案来获得当前研究上下文；它是证据库。只有要确认旧决定、附件或某个具体 worktree 的来源时，才按索引解密最小必要部分。

## 阅读后的行动原则

* 新实验先写假设、唯一变化、数据边界、预算和主指标。
* 大文件先查 manifest；不凭文件名猜用途。
* 原服务器的绝对路径只用于溯源；新机器要改为配置/项目根相对路径。
* 每个经过确认的新结论，都回写到结构化文档，而不是只留在聊天中。

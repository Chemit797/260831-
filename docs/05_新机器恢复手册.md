# 新机器恢复手册

本手册的目标是恢复研究能力，而不是复制一台旧服务器。

## A. 日常科研恢复（推荐路径）

1. 安装 Git、Python/Conda、项目依赖和 Codex；使用新机器重新登录服务。
2. 克隆控制仓库并阅读根 `AGENTS.md`。
3. 运行 `scripts/context_doctor.sh`；它会检查关键文档和 manifest 是否齐全。
4. 阅读 `projects/goai-v7-active-learning/CURRENT_STATE.md`、`NEXT_STEPS.md`、`DATA_CONTRACT.md`。
5. 配置自己的 Google Drive OAuth remote；不要迁移旧服务器的 `rclone.conf`。
6. 从 manifest 下载 V7 data、V7 baseline 和所需 AL result 包；逐个 SHA-256 校验。
7. 解压到约定的项目根目录；用路径映射/配置文件替代服务器硬编码路径。
8. 先运行小型导入/数据合同检查，再提出或执行新实验。

## B. 恢复 V7 + 主动学习研究

按以下顺序下载，避免一开始拉取无关历史：

1. `goai-v7-active-data-20260831`：官方训练输入、descriptor 与 AL semantic assets；
2. `goai-v7-three-seed-results-20260831`：V7 checkpoint/预测/指标；
3. `goai-v7-basic-descriptor-comparator-20260831`：只在复核五模型比较时需要；
4. `goai-al-v22-formal-results-20260831` 与 geometry 包：只在研究采样策略时需要；
5. BCR 结论包：仅在追溯已结束的比较时需要。

恢复后应能回答：V7 的表现来自哪三个 seed；AL 当前模型是何种 Direct MLP；两者尚缺什么接口；训练数据和语义资产的可用边界是什么。

## C. 恢复历史项目

* GeneDisco：先读 `projects/genedisco/README.md` 和复现说明；公开 dataset 重新下载，不使用旧缓存。
* GO-AI stage 1：打开 M12 离线资料包，验证 16 个权重和 submission zip；不要把历史 M10/M11 OOF 误当当前结果。
* Biohub：先 clone/解开 `main` 的 Git bundle，再分别恢复 main snapshot 和 Codex worktree patch；两份 dirty tree 不可互相覆盖。

## D. 恢复 Codex（少数情况下才需要）

日常工作不需要完整 `.codex`。先读结构化文档。若需要回溯旧会话：

1. 下载、校验并解密私有历史包到一个新目录；不要覆盖当前 `~/.codex`。
2. 用 `docs/07_Codex_会话与上下文索引.md` 找包和原始文件，而不是盲目浏览。
3. 需要恢复小型状态数据库时，先关闭 Codex 并按 `06_Codex_完整归档与恢复指南.md` 操作。
4. 永远重新登录，不恢复旧 `auth.json`、`secrets/` 或 rclone token。

## E. 验收 smoke test

恢复不是“文件解压成功”就结束。至少验证：

* `sha256sum -c` 对每个下载包通过；
* V7 三个 checkpoint、validation predictions 和报告都存在；
* 官方 metadata/proteome 与 descriptor 文件可按合同读取；
* AL source 能运行其最小测试或导入；
* 新智能体能仅根据仓库说明准确说明当前研究状态；
* 历史 Biohub worktree 的 patch 可定位到正确基线，不会覆盖 main tree。
